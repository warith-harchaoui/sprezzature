# Developer dependencies for working on the sprezzature skill.
#
# Install:
#   pip install -r requirements-dev.txt
#
# That is the whole install. The second line used to point at a per-skill
# runtime requirements file; no skill folder in this repository ships one any
# more — the model-backed scripts left with their bricks — so the line named a
# file nobody could install.

# Fast deterministic test suite under tests/
pytest>=8.0.0

# tests/conftest.py imports best_engine_ai_helper.safety to neutralise the
# NSFW scan that chat() has run on every call since 1.4: left alone it
# downloads 270 MB of classifier into every test run. The LLM/VLM scripts that
# called chat() themselves have left with their bricks, so this is now the one
# consumer in this repository — and it is a test-time import, which is why the
# dependency belongs here and not in pyproject.toml.
best-engine-ai-helper>=1.4

# Logging and the small filesystem primitives, for two scripts that already
# import it: `web/tools/render_gallery.py` and `sftp/sync_web.py` both open on
# a bare `import os_helper as osh` and call `init_logging` / `info` / `warning`
# / `error` throughout. Neither guards the import, and nothing declared it —
# so a fresh clone with this file installed got a ModuleNotFoundError from the
# first line of the gallery renderer, and from the one script whose job is to
# put the site online. Declaring what is already imported is the whole change.
#
# Here and not in pyproject.toml, deliberately. `[tool.setuptools] packages`
# ships `sprezzature/` and the ten skill folders; `web/tools/` and `sftp/` are
# in neither, so no installed copy of this package can reach these scripts. A
# base dependency would instead pull os-helper's `>=3.10,<3.14` onto this
# repository's own `requires-python = ">=3.10"`, which would then be a promise
# of a Python the dependency excludes — the defect
# `tests/test_no_brick_promises_a_python_its_dependencies_exclude.py` guards.
# The CI matrix is 3.10 / 3.11 / 3.12, well inside that window.
#
# Its two siblings in these scripts are NOT here, and the difference is the
# guard at the call site, not the weight: `sftp/sync_web.py` wraps
# `import sftp_helper` in a try/except that prints the pip line, and
# `tests/test_no_film_is_voiced_by_a_retired_engine.py` reaches
# `speaker_helper` through `pytest.importorskip`. Installing them would add 15
# and 23 packages — numpy, scipy and soundfile among them — to every job of
# every push, to wake one test that skips anyway on a `web/video` no clone has.
os-helper>=3.1.0

# Real YAML parser for SKILL.md frontmatter validation.
# Used by scripts/validate_skill.py + tests/test_validate_skill.py;
# the regex-only frontmatter check is no longer trusted as the gate.
PyYAML>=6.0

# Lint / import-hygiene gate (CODING_ALL.md rule 3, lint half), config in
# ruff.toml. audit: `ruff check .` (wired into CI) — make: `ruff check --fix .`.
# Not pinned: ruff.toml names the rules it selects, so the gate no longer
# shifts with the tool's default set — which is what the 0.15 ceiling was
# really holding back.
ruff>=0.15

# Type gate (CODING_ALL.md rule 3, type half), config in mypy.ini. Run via
# scripts/run_mypy.sh (per-skill-dir, ignore_missing_imports for heavy backends).
mypy>=1.8,<2.0
# Type stubs so the gate is deterministic across environments (yaml + requests
# are otherwise "installed but unstubbed" → import-untyped noise that varies by
# what transitive deps happen to ship).
types-PyYAML
types-requests

# deepeval, textstat and jiwer stood here, for the LLM-output quality
# assertions. Those tests left with their bricks when the monorepo was split —
# they live in sprezzature-accessibility and sprezzature-publish now, and so do
# the three dependencies. What stayed behind was an empty directory, an `eval`
# marker pytest.ini no longer declares, and three packages CI installed on
# every job of every push to run nothing at all.

# scripts/check_wheels.py parses each package's pyproject.toml. `tomllib` is
# stdlib only from 3.11 and this project supports 3.10.
tomli; python_version < '3.11'
# The kit builder runs each generator inside the staged kit, the way a reader
# would, and fifteen of them compute their geometry with numpy — the map
# projections, the 3-D surfaces, the triangulations. Declared so that a
# machine able to build kits at all (one with `sprezzature-figures`, which
# every generator imports for its fonts) does not then fall over on the
# arithmetic. Not a runtime dependency of anything this repository ships: the
# kits pin their own copy, `numpy==2.3.5`.
numpy>=1.24
