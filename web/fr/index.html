Premiers pas

Sprezzature, ce sont des skills pour Claude Code ou OpenCode. Installez ceux que vous voulez, puis demandez en français. Le skill produit l'artefact et l'audite.

1 · Installer

Récupérez la dernière release, copiez les skills voulus dans votre environnement.

VERSION=1.0.0    # dernier tag sur la page des releases
curl -L https://github.com/warith-harchaoui/sprezzature/releases/download/v${VERSION}/sprezzature-skills-${VERSION}.tar.gz | tar xz

mkdir -p ~/.claude/skills          # OpenCode : ~/.opencode/skills
cp -r sprezzature-ui sprezzature-figures ~/.claude/skills/

Vous ne voulez qu’un seul outil, sans agent ? Chaque outil déterministe existe aussi en paquet pip autonome. Voir Paquets.

2 · Demander, en français

Les phrases déclencheuses aiguillent la demande ; le skill la produit, puis l'audite selon les règles.

  • « rends cette page accessible » → sprezzature-accessibility audite le HTML et liste quoi corriger.
  • « fais une figure de ce CSV » → sprezzature-figures la dessine, puis audite le graphique.
  • « transforme ce CLI en interface » → sprezzature-cli-gui échafaude une interface utilisable.

Points forts

👁️ Regardez la figure avant de la livrer

Un texte, on le relit. Une figure, non : ce qui cloche est dans les pixels, pas dans le code. La Ralph Eyeball Loop prend donc ce que vous avez fait (un graphique Vega, une figure TikZ, un diagramme Mermaid, une page entière) et en fait une image avec un outil déterministe, sans aucun modèle. Ensuite, quelqu'un la regarde pour de vrai : par défaut l'agent lui-même, celui qui a écrit le code ou bien, entièrement hors ligne, un modèle de vision local optionnel. Il repère ce qu'aucun contrôle du code ne verra : une étiquette coupée au bord, une légende partie hors cadre, deux nœuds l'un sur l'autre, des couleurs qui disparaissent pour un daltonien. Vous corrigez la source, vous refaites l'image, vous regardez encore. C'est une boucle de revue prescrite, pas un critique autonome. Les autres réservent l'astuce aux pages web. Nous, on l'applique aussi aux graphiques et aux diagrammes.

📐 La figure est un vrai SVG, pas une image

Une figure se livre en scalable vector graphics (SVG, graphiques vectoriels) écrit avec soin. Les générateurs produisent le balisage directement, chacun avec son viewBox, si bien que le graphique s'adapte à toute taille sans un pixel flou et que le texte reste sélectionnable. Vega-Lite est un moyen commode de décrire un graphique, mais son JavaScript Object Notation (JSON) n'est pas ce qu'on livre, et le Portable Network Graphics (PNG) n'est qu'un export pour les endroits qui ne prennent pas le vectoriel. Le livrable, c'est le SVG.
