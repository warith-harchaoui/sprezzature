    sprezzature-publish

    Publication

    Transforme un dossier de Markdown en site statique  : balises meta par page pour le SEO (search engine optimization, le référencement : faire qu'une page sorte bien placée quand on la cherche sur Google), un jeu complet de favicons / icônes d'application web progressive (PWA) depuis un logo, robots + sitemap + llms.txt + flux, réécritures en langage clair et narration en synthèse vocale (TTS) locale.

    SKILL.md (la spec agent) ⭐ sur GitHub

    Produit

    • Open Graph (OG) + Twitter Card + Schema.org JSON-LD (JSON for Linked Data, une fiche au format JSON, du texte en champs nommés, qu'un moteur de recherche lit pour savoir de quoi parle la page) par page
    • Un jeu complet de favicons / icônes d'app / PWA depuis un logo, plus un webmanifest
    • robots.txt, sitemap.xml, llms.txt, Atom / flux Really Simple Syndication (RSS), humans.txt
    • Réécritures en langage clair et narration audio (MP3) via TTS libre (OSS) locale
    • Une lecture synchronisée liée à cette narration, qui surligne la phrase prononcée — et qui s’applique aussi à une page HTML existante sans Markdown derrière

    Audite

    • Linter le Markdown et détecter les liens cassés avant publication
    • Contrôles de lisibilité / niveau de lecture sur le texte
    • L’audio et la page quittent le même Markdown par deux routes : les deux listes de phrases sont comparées et le premier écart refuse. Une lecture décalée d’une phrase vaut moins que pas de surlignage : elle désigne la mauvaise ligne avec aplomb

    Dites l'une de ces phrases

    La skill se déclenche sur une formulation de ce type, sans commande à mémoriser.

    markdown en site balises meta carte OG SEO GEO favicons robots.txt sitemap llms.txt flux Atom langage clair narre cet article lint markdown

    Questions fréquentes

    Comment installer sprezzature-publish ?

    Lancez pip install sprezzature-publish sous Python 3.10 à 3.13 : cette seule ligne installe les treize outils, l'API (Application Programming Interface, la porte où frappent les autres programmes : un script envoie ses chiffres et reçoit une réponse) servie en HTTP (HyperText Transfer Protocol, le protocole par lequel un navigateur demande une page à un serveur) et le serveur MCP (Model Context Protocol, le protocole par lequel les agents IA appellent des outils en français), sans option à choisir. sprezzature-publish est gratuit et open source sous licence BSD (Berkeley Software Distribution, une licence née à l'université de Berkeley : chacun peut réutiliser le code, même pour le vendre, en citant l'auteur), version 3-Clause, sans compte ni clé d'API.

    De quoi sprezzature-publish a-t-il besoin en plus de pip ?

    sprezzature-publish n'a besoin d'Ollama sur votre machine que pour les outils qui interrogent un modèle local : sprezzature-publish-meta, sprezzature-publish-plain, sprezzature-publish-faq (sauf avec --no-llm), sprezzature-publish-lint --ai et sprezzature-publish-narrate --ai-hints. Le lint, le rendu, les icônes, les index, les audits et la vérification des appels à l'action se passent de modèle. La narration demande une fois ses fichiers de voix, téléchargés par sprezzature-audio-install-voice --engine kokoro.

    sprezzature-publish envoie-t-il mon contenu dans le cloud ?

    Non : sprezzature-publish tourne en local. Les balises meta, les réécritures en langage clair et les réponses de FAQ sont rédigées par un modèle servi par Ollama sur votre machine, et la narration est synthétisée par un moteur de synthèse vocale open source local. Auditer une URL en ligne lit la page sans jamais y écrire.

    sprezzature-publish gère-t-il le SEO, le GEO (generative engine optimization, faire que les assistants IA comme ChatGPT citent la page dans leurs réponses), l'AEO (answer engine optimization, être la réponse directe qu'affiche un moteur à une question posée) et llms.txt ?

    Oui : sprezzature-publish couvre les quatre, et sprezzature-publish-findable produit un seul rapport pour les moteurs de recherche, génératifs et de réponse (SEO, GEO, AEO), pages qui rapportent en tête, et --fix applique les réparations déterministes. sprezzature-publish-indexes écrit robots.txt, sitemap.xml, llms.txt, llms-full.txt, un flux Atom ou RSS et humans.txt, et --offer et --cta placent ce à quoi sert le site en tête de llms.txt.

    sprezzature-publish peut-il écrire une FAQ avec le JSON-LD FAQPage ?

    Oui : sprezzature-publish rédige avec sprezzature-publish-faq la FAQ qui manque à un site, à partir de ses propres pages, classe les questions selon les appels à l'action déclarés dans ctas.yaml et met à part celles auxquelles le site ne sait pas encore répondre. sprezzature-publish-faq site/ --audit --fix reconstruit le JSON-LD FAQPage depuis la FAQ visible, et l'outil ne prétend jamais que ce balisage fait remonter une page.

    sprezzature-publish peut-il lire un article de blog à voix haute ?

    Oui : sprezzature-publish lit à voix haute, avec une voix locale, un article Markdown ou une page HTML (avec --scope) grâce à sprezzature-publish-narrate, et écrit la piste minutée à côté du WAV (Waveform Audio File Format, le fichier son brut, non compressé, qu'écrit un enregistreur) ou du MP3. sprezzature-publish-readalong la lie ensuite à la page pour surligner la phrase lue, et son --check repère une page modifiée après l'enregistrement. Les voix viennent de sprezzature-audio, installé avec lui.

    En quoi sprezzature-publish diffère-t-il de MkDocs, Hugo, Jekyll ou Yoast ?

    sprezzature-publish est taillé pour un README, un dossier docs/ et un blog : pour cent pages versionnées ou une équipe, MkDocs Material, Hugo ou Astro conviennent mieux, et son propre README le dit. Contrairement à un plugin SEO comme Yoast, qui travaille dans un CMS (content management system, un logiciel comme WordPress où l'on écrit les pages dans un formulaire au lieu de les coder), il construit les pages et sait aussi auditer et réparer l'en-tête d'un site qu'il n'a pas construit. Il y ajoute un jeu d'icônes tiré d'un seul logo, llms.txt, une FAQ sourcée et une lecture accompagnée.

    Peut-on lancer sprezzature-publish en CI (continuous integration, l'intégration continue : un serveur relance les tests à chaque modification du code), sans Claude Code ?

    Oui : sprezzature-publish fonctionne sans agent, comme bibliothèque Python, ligne de commande, API HTTP avec une image Docker qui lance sprezzature-publish-mcp, et serveur MCP. En CI, sprezzature-publish-lint sort en code 1 sur toute erreur avec seulement click et la bibliothèque standard, et sprezzature-publish-audit comme sprezzature-publish-findable sortent en code 1 sur une erreur, avec --format json pour une lecture par machine.
