    sprezzature-ui

    Génération d'interface utilisateur (UI)

    UI vanilla JavaScript (JS) + Tailwind : composants, pages, formulaires, dialogues, tableaux de bord, pour les équipes qui livrent des outils internes sans designer.

    SKILL.md (la spec agent) ⭐ sur GitHub

    Produit

    • HTML (langage de balisage des pages web) sémantique + Tailwind : formulaires, modales, navigation, tableaux de bord, tables de données, réglages, états vides, squelettes
    • Variantes en mode sombre, anneaux de focus, garde-fous d'animation réduite par défaut
    • La règle des trois Roboto (sans + serif + mono), en respectant toute police que vous nommez
    • i18n extrait dans un seul fichier de configuration YAML (YAML Ain't Markup Language, un format texte de réglages, une ligne « clé : valeur » par réglage, qu'on lit et corrige à la main) partagé entre interface graphique (GUI) et prompts — un prompt de modèle est une chaîne traduisible, ce que presque personne ne reconnaît

    Audite

    • Auditer une UI existante selon les conventions de sprezzature-ui et d'ergonomie
    • Auditer la couverture i18n et repérer les chaînes non traduites : traductions enfouies dans du JavaScript et du HTML, prompts écrits en dur en Python
    • La correction écrit chaque chaîne dans le catalogue, puis s’arrête. Elle ne réécrira pas votre appel — vous seul savez si cette ligne réclame un pluriel ou une variable — donc elle imprime la ligne à coller, et signale ce qu’elle n’a pas su analyser avec certitude

    Questions fréquentes

    Comment installer sprezzature-ui ?

    Lancez pip install sprezzature-ui (Python 3.10 ou plus récent) : une seule installation apporte l'audit i18n, les outils de catalogue, la commande sprezzature-ui, l'API (Application Programming Interface, la porte où frappent les autres programmes : un script envoie ses chiffres et reçoit une réponse) servie en HTTP (HyperText Transfer Protocol, le protocole par lequel un navigateur demande une page à un serveur) et le serveur MCP (Model Context Protocol, le protocole par lequel les agents IA appellent des outils en français), sans option à choisir. La moitié qui écrit l'interface est la skill : pip install sprezzature puis sprezzature-skills --install, ou sprezzature-skills --install --agent opencode pour OpenCode.

    Quel code sprezzature-ui produit-il ?

    sprezzature-ui guide un agent pour écrire du HTML sémantique, des classes utilitaires Tailwind et des modules ES (ECMAScript, le nom officiel de JavaScript : des fichiers de code qui s'importent les uns les autres) simples, sans React, Vue ni aucun autre framework à l'exécution. Variantes pour le mode sombre, anneaux de focus visibles et garde-fous de mouvement réduit sont actifs par défaut, et la typographie suit la règle des trois Roboto : Roboto, Roboto Serif et Roboto Mono, hébergées localement, sauf si vous nommez une autre fonte.

    Peut-on utiliser sprezzature-ui sans Claude Code ?

    En partie : les outils i18n de sprezzature-ui fonctionnent seuls, comme bibliothèque Python, ligne de commande, API HTTP avec image Docker et serveur MCP, sprezzature-ui-mcp. Écrire l'interface elle-même revient au modèle, guidé par la skill et par la prose de son dossier references/ : cette moitié demande un agent comme Claude Code ou OpenCode.

    Que vérifie l'audit de sprezzature-ui, et peut-il tourner en CI (continuous integration, l'intégration continue : un serveur relance les tests à chaque modification du code) ?

    L'audit de sprezzature-ui, sprezzature-ui-i18n-audit, signale les tables de traduction intégrées au JavaScript ou au HTML (règle I18N001) et les prompts de LLM (large language model, un grand modèle de langage, le moteur d'un assistant comme ChatGPT ou Claude) écrits en dur dans du Python, en constantes dont le nom contient PROMPT ou INSTRUCTION (règle I18N002). Il sort avec le code 1 à la moindre trouvaille, de quoi faire échouer une CI ou servir de crochet pre-commit, déclaré dans le dépôt ; il ne juge pas la qualité d'une traduction.

    Comment sprezzature-ui gère-t-il les traductions en YAML ?

    sprezzature-ui range toutes les chaînes à traduire, libellés d'interface comme prompts de modèle, dans un seul catalogue, locales/i18n.yaml. sprezzature-ui-i18n-make le crée, le compile en locales/i18n.json et écrit deux chargeurs, locales/i18n.js pour le navigateur et locales/i18n_prompts.py pour Python ; sprezzature-ui-i18n-audit --fix déplace les chaînes trouvées dans le catalogue et affiche l'appel à coller, sans réécrire votre code.

    sprezzature-ui envoie-t-il mon code dans le cloud ?

    Non : l'audit et les outils de catalogue de sprezzature-ui lisent vos fichiers en local, sans réseau ni modèle, donc sans Ollama ; l'audit n'importe que la bibliothèque standard de Python. Le code de l'interface est écrit par votre agent, qui suit la politique de données de son fournisseur.

    Quelle différence entre sprezzature-ui et shadcn/ui, v0 ou Bootstrap ?

    shadcn/ui fournit des composants React et Bootstrap une large bibliothèque de composants, alors que sprezzature-ui refuse tout framework à l'exécution et propose des règles écrites et quelques composants à copier. v0 construit une application à partir d'un prompt, dans un compte hébergé ; sprezzature-ui travaille avec l'agent que vous employez déjà et vérifie le résultat par des audits déterministes.

    sprezzature-ui est-il gratuit ?

    Oui. sprezzature-ui est open source sous licence BSD (Berkeley Software Distribution, une licence née à l'université de Berkeley : chacun peut réutiliser le code, même pour le vendre, en citant l'auteur), version 3-Clause, sans compte, sans clé d'API ni offre payante, et son code est sur GitHub.
