    sprezzature-ux-laws

    Lois de l'expérience utilisateur (UX)

    Applique les Lois de l'UX canoniques (Jon YABLONSKI) au JavaScript (JS) standard + Tailwind : à la création d'interface utilisateur (UI) comme à l'audit de HTML (langage de balisage des pages web) existant. La référence couvre 30 lois avec déclencheur / action / hook Tailwind.

    SKILL.md (la spec agent) ⭐ sur GitHub

    Produit

    • Concevoir un écran avec Hick / Fitts / Miller / Peak-End en tête
    • Chaque loi associée à un hook Tailwind concret

    Audite

    • L'auditeur statique signale le sous-ensemble détectable mécaniquement : Hick, Miller, Fitts, Jakob, Tesler, Aesthetic-Usability, Attention sélective, Choice Overload (huit vérifications)
    • Sévérité + sortie JSON (notation d'objets JavaScript) pour pré-commit / intégration continue (CI)

    Questions fréquentes

    Comment installer sprezzature-ux-laws ?

    Lancez pip install sprezzature-ux-laws sous Python 3.10 ou plus récent : une seule installation donne la bibliothèque, les deux commandes, l'API HTTP et le serveur MCP, sans option à choisir. sprezzature-ux-laws est gratuit et open source sous licence BSD 3-Clause.

    Quelles lois de l'UX sprezzature-ux-laws vérifie-t-il ?

    sprezzature-ux-laws vérifie huit des trente lois de lawsofux.com, celles qu'une lecture du code HTML peut trancher : hick, choice-overload, miller, jakob, fitts, aesthetic-usability, selective-attention et tesler. Deux d'entre elles, hick et jakob, sont des erreurs et les six autres des avertissements ; --only et --ignore choisissent parmi elles par leur nom.

    Que change sprezzature-ux-laws --fix ?

    sprezzature-ux-laws répare quatre lois avec --fix : il ajoute min-h-11 pour Fitts, un anneau de focus focus-visible:ring-2 pour l'effet esthétique-utilisabilité, découpe les longs codes en groupes de quatre séparés par des espaces insécables pour Miller, et réécrit un div ou un span cliquable en vrai button pour Jakob. Les quatre autres demandent une décision de conception, pas une retouche du texte. --fix --dry-run montre les modifications d'avance, et un second passage sur un fichier réparé n'en applique aucune.

    Comment sprezzature-ux-laws compte-t-il les choix d'un menu responsive ?

    sprezzature-ux-laws compte ce qu'un écran montre, pas les liens du fichier : il lit la visibilité de chaque contrôle dans ses classes d'affichage Tailwind et retient le pire du compte mobile et du compte bureau, si bien qu'une rangée de bureau et un menu hamburger ne s'additionnent pas. Un details, un dialog, un menu ou un tablist compte pour un seul choix, et plus de sept choix dans un nav sur un même écran font une erreur de Hick.

    sprezzature-ux-laws envoie-t-il mes pages dans le cloud ?

    Non : sprezzature-ux-laws lit le HTML brut avec l'analyseur de la bibliothèque standard de Python, sans navigateur, sans réseau et sans modèle d'IA, et n'a donc besoin de rien d'autre que pip. C'est ce qui le garde déterministe et assez rapide pour un hook pre-commit.

    En quoi sprezzature-ux-laws diffère-t-il de Lighthouse ou d'une revue de design ?

    sprezzature-ux-laws ne lit que le code source : il attrape les fautes mécaniques sans navigateur, mais ne peut ni afficher une page ni regarder quelqu'un s'en servir. Lighthouse et les données de terrain mesurent le temps de réponse, le seuil de Doherty qu'il laisse explicitement de côté, et seule une revue de design ou une séance avec de vrais utilisateurs dit si un écran a du sens ; il sert à ce que les fautes mécaniques n'y arrivent jamais.

    Peut-on lancer sprezzature-ux-laws en CI ?

    Oui : sprezzature-ux-laws sort en code 1 quand sprezzature-ux-laws site/ trouve au moins une erreur, ou le moindre constat avec --strict, et en code 2 sur une erreur d'usage. --json imprime un objet par constat, avec la loi, la gravité, le chemin, la ligne, le message et l'extrait, qu'une CI peut lire.

    Peut-on se servir de sprezzature-ux-laws sans Claude Code ?

    Oui : sprezzature-ux-laws est une bibliothèque Python (audit_html, audit_file, fix_file), une ligne de commande, une API HTTP avec une image Docker qui lance sprezzature-ux-laws-mcp, et un serveur MCP dont les outils sont health, list_laws et audit_interface. La skill qui dit à Claude Code ou OpenCode quand appliquer les lois s'installe avec pip install sprezzature, puis sprezzature-skills --install.
